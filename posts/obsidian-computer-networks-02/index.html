三大可靠传输协议

2025-12-01 updated 2025-12-01 6 min
  • 概述
  • 对比总览
  • 分协议详解
  • 1. 停止-等待协议 (S-W)
  • 2. 后退N帧协议 (GBN)
  • 3. 选择重传协议 (SR)

概述

可靠传输协议通过确认（ACK） 和超时重传机制，确保数据帧能够正确、有序地交付给接收方。主要分为三种协议：

  1. 停止-等待协议（Stop-and-Wait, S-W）
  2. 后退N帧协议（Go-Back-N, GBN）
  3. 选择重传协议（Selective Repeat, SR）

三者核心区别在于滑动窗口的大小以及由此带来的确认和重传策略的不同。

分协议详解

1. 停止-等待协议 (S-W)

  • 窗口大小：WT=1W_T = 1WT​=1，WR=1W_R = 1WR​=1。是单帧滑动窗口。
  • 序号编码：1比特 (0和1交替) 即可满足需求。
  • 运行过程：
    1. 发送方发送0号帧，启动定时器。
    2. 接收方正确收到0号帧，回发ACK0。
    3. 发送方收到ACK0，停止定时器，发送1号帧，启动新定时器。
    4. 若数据帧或ACK丢失/出错，发送方定时器超时，则重传上一个帧。
  • 关键点：
    • 发送方必须在其缓存中保留已发送帧的副本，直到收到对应的ACK。
    • 接收方收到重复帧（序号相同）时，将其丢弃，并重传上一次发送的ACK（防止ACK丢失）。
  • 缺点：信道利用率 U=TDTD+RTT+TAU = \frac{T_D}{T_D + RTT + T_A}U=TD​+RTT+TA​TD​​很低（TDT_DTD​为发送时延，TAT_ATA​为发送确认时延）。

2. 后退N帧协议 (GBN)

  • 窗口大小：WT>1W_T > 1WT​>1 (通常 WT=2n−1W_T = 2^n - 1WT​=2n−1)，WR=1W_R = 1WR​=1。
  • 运行过程：
    1. 发送方可以连续发送窗口内的所有帧。
    2. 接收方只按序接收。如果收到正确的第n帧，则交付上层，回发累计确认ACKn (表示n及之前所有帧已正确接收)。
    3. 若第k帧出错或丢失，接收方会丢弃所有后续的帧（k+1, k+2, …），并持续发送最后一个正确接收的帧的确认（如ACK(k-1)）。
    4. 发送方为最早发出的未确认帧维护一个定时器。若定时器超时，则重传所有已发出但未收到确认的帧（即从第k帧开始重传）。
  • 命题追踪：
    • GBN工作原理 (2009)：核心是累计确认和回退N步重传。
    • GBN确认号的含义 (2017)：ACKn是累计确认，代表期望收到n+1号帧。
    • GBN发送窗口最大尺寸 (2017)：WTmax=2n−1W_T^{max} = 2^n - 1WTmax​=2n−1。若WT=2nW_T = 2^nWT​=2n，会造成接收方无法区分新帧和旧帧（序号产生重叠）。
  • 缺点：单个帧出错可能导致大量帧被重传，信道利用率随误码率升高而急剧下降。

3. 选择重传协议 (SR)

  • 窗口大小：WT>1W_T > 1WT​>1, WR>1W_R > 1WR​>1。且必须满足 WR+WT≤2nW_R + W_T \leq 2^nWR​+WT​≤2n 和 WR≤WTW_R \leq W_TWR​≤WT​ ⇒ WRmax=WTmax=2n−1W_R^{max} = W_T^{max} = 2^{n-1}WRmax​=WTmax​=2n−1。
  • 运行过程：
    1. 发送方连续发送窗口内的帧，并为每个未确认的帧单独启动定时器。
    2. 接收方缓存所有正确接收且序号落在WRW_RWR​内的帧（无论是否按序）。
    3. 接收方对每个正确接收的帧进行逐个确认 (发送ACKn)。如果收到乱序的帧，先缓存起来。
    4. 当窗口内序号最小的帧被接收后，就将一连串按序的帧交付上层，接收窗口向前滑动。
    5. 发送方只重传超时未确认的帧。接收方还可发送否定确认NAK，要求发送方立即重传指定帧。
  • 命题追踪：
    • SR原理及实现 (2011, 2024)：核心是接收方设置缓存、逐个确认、选择性重传。
  • 优点：避免了GBN中重复传输正确帧的问题，信道利用率高。
  • 缺点：实现最复杂，发送方和接收方都需要更大的缓存空间来维护窗口中的每个帧。

总结：从S-W到GBN再到SR，通过增大窗口和优化重传策略，信道利用率和性能逐步提升，但实现复杂度也相应增加。
