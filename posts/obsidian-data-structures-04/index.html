核心思想

KMP 算法的精髓在于：当模式串与主串发生失配时，模式串能够向右“智能地”滑动多位，而不是仅仅一位。next 数组和 nextval 数组就是用来指导这个“智能滑动”的。

1. next 数组

定义：next[j] 表示在模式串的第 j 个字符（下标从 1 开始）与主串发生失配时，下一次匹配 应该跳转到模式串的哪个位置（下标）去与主串当前失配的字符进行比较。

求法（手动计算，下标从1开始）： next[j] 的值为 模式串的前 j-1 个字符组成的子串 中，其 最长相等真前缀（不包含自身）和真后缀 的长度 + 1。

  • 真前缀/后缀：不包含字符串本身的前缀或后缀。
  • 最长相等：找到那个最长的、相同的前缀和后缀。

计算步骤：

  1. next[1] = 0。这是一个约定，表示模式串的第一个字符就失配，主串需要向后移动一位，模式串从头开始匹配。
  2. 对于 j > 1，找出子串 P[1 ... j-1] 的最长相等真前缀和真后缀的长度 k，则 next[j] = k + 1。
  3. 如果找不到这样的前后缀（即长度为0），则 next[j] = 1。

例子：模式串 "ababaaababaa"

如何使用 next 数组？ 假设在 j=7 (字符 ‘a’) 的位置失配。查表 next[7] = 2。这意味着我们不需要从模式串头开始，而是将模式串向右滑动，让模式串的第 2 个字符 ‘b’ 对齐到主串当前失配的位置，继续进行比较。

2. nextval 数组 (next 数组的优化)

问题：next 数组在某些情况下存在“无效跳转”。 观察上面的例子，当 j=4 时，P[4] = ‘b’，next[4] = 2，而 P[2] 也是 ‘b’。如果 P[4] 与主串失配，说明主串当前字符不等于 ‘b’。那么跳转到 P[2] (也是 ‘b’) 去比较，结果必然还是失配。这次跳转是多余的。

定义：nextval 数组在 next 数组的基础上，消除了这种连续相同字符导致的无效跳转。

求法（基于 next 数组）：

  1. nextval[1] = 0。
  2. 对于 j 从 2 到模式串长度：
    • 如果 P[j] == P[next[j]]，则 nextval[j] = nextval[next[j]]。
    • 否则，nextval[j] = next[j]。

解释：

  • 如果失配位置的字符 与 它要跳转到的位置的字符 相同，那么这个跳转后的比较也必然失败。所以我们可以“提前”进行这个跳转，直接使用跳转后那个位置的 nextval 值。
  • 如果不同，那么这次跳转是有效的，直接使用 next 值即可。

例子：使用同一个模式串 "ababaaababaa"

对比 next 和 nextval 的效果： 假设在主串 ...ababac... 与模式串 "ababaaababaa" 匹配时，在 j=5 (字符 ‘a’) 的位置与主串的 ‘c’ 失配。

  • 使用 next：next[5] = 3，跳转到 j=3 的 ‘a’ 继续比较。
  • 使用 nextval：nextval[5] = 0，直接跳转到 j=0。根据规则，j=0 意味着模式串第一个字符也已失配，主串指针后移一位，模式串从头开始。这比 next 数组少了一次必然失败的比较。
