一、ARP协议

1. 概述：ARP的作用

  • 核心问题：网络层使用IP地址进行寻址，而数据链路层使用MAC地址（硬件地址）来实际传输帧。一台主机如何知道目标IP地址对应的MAC地址？
  • 解决方案：地址解析协议 (Address Resolution Protocol, ARP) 应运而生。它负责根据本网内的IP地址解析出其对应的MAC地址。
  • 工作层次：虽然ARP的功能是为网络层服务，但它严格来说是一个工作在数据链路层之上的协议，它的报文是直接封装在数据链路层帧中传输的。

2. ARP的工作原理与报文

2.1 基本原理

  1. ARP缓存表：每台主机和路由器都维护一个ARP缓存表，存放着{IP地址 : MAC地址}的映射关系，并设有生存时间（TTL）。
  2. ARP请求 (广播)：当需要解析一个未知的IP地址时，主机会在本局域网内广播一个 “ARP请求报文” ，内容大致是：“我的IP和MAC是XX，谁的IP是YY？请告诉你的MAC地址。”
  3. ARP响应 (单播)：局域网内所有主机都会收到该请求，但只有IP地址匹配的目标主机会响应该请求，向请求方单播一个 “ARP响应报文” ，告知其MAC地址。
  4. 更新缓存：请求方收到响应后，将得到的IP:MAC映射存入自己的ARP缓存表，以备后续使用。

2.2 ARP报文封装

  • ARP报文是直接封装在数据链路层的帧中进行传输的。
  • 封装时，帧首部的类型字段 (Type) 会设置为 0x0806，以表明帧的数据部分是一个ARP报文。

3. ARP的四种典型应用场景

这四种场景是理解ARP和整个网络通信过程的关键。我们假设有一个由两个路由器互联的三个网络组成的拓扑（网1 -- R1 -- 网2 -- R2 -- 网3）。

参考上图，有以下四种场景

场景一：本网络内，主机到主机

  • 描述：发送方是主机（如 H1），要把IP数据报发送到本网络上的另一台主机（如 H3，假设H3在网1）。
  • ARP过程：H1 首先检查目标IP地址 H3 是否在同一网段。确认后，H1 在网1内广播ARP请求，询问 H3 的MAC地址。H3 收到后，单播回应自己的MAC地址。
  • 后续操作：H1 获取到 H3 的MAC地址后，将IP数据报封装成目的地址为 H3-MAC 的帧，直接发送给 H3。

场景二：跨网络，主机到主机（需经过网关）

  • 描述：发送方是主机（如 H1），要把IP数据报发送到其他网络上的一台主机（如 H4，在网3）。
  • ARP过程：H1 通过计算，发现目标IP H4 不在本网段。因此，它不会去解析 H4 的MAC地址（因为也解析不到），而是需要将数据报先发给默认网关（即 R1 的接口 L1）。于是，H1 在网1内广播ARP请求，询问网关 L1 的IP地址对应的MAC地址。
  • 后续操作：H1 获取到 L1 的MAC地址后，将IP数据报封装成目的地址为 L1-MAC、但目的IP仍是 H4 的帧，发送给路由器 R1。剩下的工作由路由器 R1来完成。

场景三：路由器到本网络主机

  • 描述：发送方是路由器（如 R1），需要把IP数据报转发到与它直接相连的网络（网2）上的一台主机（如 H3）。
  • ARP过程：路由器 R1 查询路由表后，确定下一跳就是目标主机 H3 本身。于是，R1 在网2内广播ARP请求，询问 H3 的MAC地址。H3 回应。
  • 后续操作：R1 获取到 H3 的MAC地址后，将IP数据报封装成目的地址为 H3-MAC 的帧，从它的 L2 接口直接发送给 H3。

场景四：路由器到路由器（下一跳）

  • 描述：发送方是路由器（如 R1），需要把IP数据报转发给另一个路由器（如 R2），以最终到达目标网络（网3）。
  • ARP过程：路由器 R1 查询路由表后，确定下一跳是路由器 R2 的接口 L3。于是，R1 在网2内广播ARP请求，询问下一跳地址 L3-IP 对应的MAC地址（即 L3-MAC）。R2 的 L3 接口回应。
  • 后续操作：R1 获取到 L3-MAC 后，将IP数据报封装成目的地址为 L3-MAC、但目的IP仍是最终目标 H4 的帧，发送给路由器 R2。剩下的工作由 R2 来完成。

关键点总结：

  1. 通信双方是否在同一网段，决定了ARP解析的目标是谁。
  2. 只要跨网络通信，源主机ARP解析的目标一定是其默认网关的MAC地址。
  3. 路由器在转发时，每跳都会重新封装MAC帧，源和目的MAC地址都会改变，但内部的IP首部（源IP和目的IP）始终不变。

二、DHCP协议

1. 概述：为什么需要DHCP？

  • 核心问题：为局域网内的每一台主机手动配置IP地址、子网掩码、默认网关和DNS服务器地址是一项繁琐且容易出错的工作。
  • 解决方案：动态主机配置协议 (Dynamic Host Configuration Protocol, DHCP) 应运而生。它允许一台主机从网络中的DHCP服务器自动获取IP地址等配置信息。
  • 工作模式：即插即用。主机接入网络后，无需任何手动配置即可上网。
  • 工作层次：DHCP是一个应用层协议，它使用UDP作为其传输层协议。DHCP服务器侦听67端口，DHCP客户端使用68端口。

2. DHCP的工作过程（DORA）

DHCP客户机与服务器的交互过程遵循经典的DORA四步流程（Discover, Offer, Request, Acknowledge）。整个过程都使用广播进行。

步骤一：DHCP发现 (DHCP Discover)

  • 发起者：DHCP客户端。
  • 时机：客户端启动时（或租约到期需要续约时）。
  • 操作：客户端在本地物理子网内广播一个 DHCP Discover 报文。
  • 报文细节：
    • 源IP地址：0.0.0.0 （因为客户端还没有IP地址）
    • 目的IP地址：255.255.255.255 （受限广播地址）
    • 源MAC地址：客户端自己的MAC地址
    • 目的MAC地址：FF:FF:FF:FF:FF:FF （广播MAC地址）
  • 目的：寻找网络中的DHCP服务器，并请求一个IP地址。

步骤二：DHCP提供 (DHCP Offer)

  • 发起者：DHCP服务器。
  • 操作：收到DHCP Discover报文的服务器，从自己的IP地址池中选择一个可用的IP地址，然后广播一个 DHCP Offer 报文作为响应。
  • 报文细节：
    • 源IP地址：DHCP服务器自己的IP地址
    • 目的IP地址：255.255.255.255 （仍然是广播）
    • 报文内容：包含为客户端预分配的IP地址、子网掩码、租期（Lease Time）、默认网关、DNS服务器等配置信息。
  • 目的：告知客户端，“我可以为你提供这个IP地址”。

注意：为什么第二步还是广播？因为此时客户端还没有IP地址，如果服务器单播回复，客户端无法识别是否是发给自己的。

步骤三：DHCP请求 (DHCP Request)

  • 发起者：DHCP客户端。
  • 操作：客户端可能会收到多个服务器的DHCP Offer（如果网络中有多个DHCP服务器）。它会选择第一个或最好的一个Offer，然后向网络广播一个 DHCP Request 报文。
  • 报文细节：
    • 源IP地址：0.0.0.0
    • 目的IP地址：255.255.255.255
    • 报文内容：明确指明它选择接受哪个服务器的哪个IP地址。
  • 目的：
    1. 告知被选中的服务器：“我决定使用你提供的IP地址”。
    2. 告知其他未被选中的服务器：“谢谢你们的Offer，但我现在不需要了”，以便它们释放预分配的IP地址。

步骤四：DHCP确认 (DHCP ACK)

  • 发起者：被选中的DHCP服务器。
  • 操作：服务器收到DHCP Request后，确认该IP地址的分配，并向客户端广播一个 DHCP ACK 报文。
  • 报文细节：
    • 源IP地址：服务器自己的IP地址
    • 目的IP地址：255.255.255.255
    • 报文内容：包含客户端所请求的IP地址的所有正式配置参数。
  • 目的：正式完成IP地址的分配过程。客户端收到DHCP ACK后，即可使用该IP地址进行网络通信。

3. 租期与续租

DHCP分配的IP地址是有租期 (Lease Time) 的（如8天）。租期到了之后，地址会被服务器收回。

  1. 租期过半 (T1)：客户端会尝试向原服务器单播一个DHCP Request来续租。如果原服务器同意，则会回复一个DHCP ACK，并重置租期。
  2. 租期过87.5% (T2)：如果第一次续租失败，客户端会广播一个DHCP Request，请求任何DHCP服务器延长租期。
  3. 租期到期：如果两次续租都失败，客户端必须停止使用当前IP地址，并重新发起DHCP Discover过程。

4. 为什么全程使用广播？

这是理解DHCP的关键。根本原因在于：在完成整个DORA过程之前，客户端没有一个有效的IP地址。因此，服务器无法通过单播IP数据报与之通信。使用广播（MAC层广播和IP层广播）确保了通信双方在地址未知的情况下依然能够完成交互。

三、难点题出发的各种报文传播方式汇总

核心概念辨析

在分析具体协议之前，必须牢记两个关键点：

  1. 网络层广播：指目的IP地址是广播地址（如255.255.255.255或Net-id.255.255.255）。
  2. 数据链路层广播：指目的MAC地址是广播地址（FF:FF:FF:FF:FF:FF）。
  3. 单播：目的IP和目的MAC都是某一个特定设备的地址。

这两种广播在不同层级独立工作，一个报文可以同时是IP广播和MAC广播，也可以是IP广播但MAC单播。

ARP报文传播类型

1. ARP请求 (ARP Request)

  • 网络层 (IP)：
    • 目的IP地址：要解析的目标IP地址（这是一个单播IP地址）。
    • 例如，H1要解析H2的MAC，目的IP就是H2的IP。
  • 数据链路层 (MAC)：
    • 目的MAC地址：FF:FF:FF:FF:FF:FF （广播MAC地址）。
    • 因为此时H1还不知道H2的MAC，所以必须广播让所有人都听到。
  • 结论：目的IP是单播，目的MAC是广播。

2. ARP响应 (ARP Reply)

  • 网络层 (IP)：
    • 目的IP地址：发起请求的主机的IP地址（这是一个单播IP地址）。
    • 例如，H2回应H1，目的IP就是H1的IP。
  • 数据链路层 (MAC)：
    • 目的MAC地址：发起请求的主机的MAC地址（这是一个单播MAC地址）。
    • 因为H2已经从请求报文中知道了H1的MAC地址，可以直接回复。
  • 结论：目的IP是单播，目的MAC是单播。

DHCP报文传播类型 (DORA过程)

DHCP的过程更特殊，因为客户端在获得配置之前没有IP地址。

1. DHCP发现 (DHCP Discover) & 3. DHCP请求 (DHCP Request)

这两个报文的发送方和地址特性完全相同。

  • 发送方：客户端（无IP地址状态）。
  • 网络层 (IP)：
    • 目的IP地址：255.255.255.255 （受限广播IP地址）。
    • 因为客户端不知道网络中存在谁，只能向全世界喊话。
  • 数据链路层 (MAC)：
    • 目的MAC地址：FF:FF:FF:FF:FF:FF （广播MAC地址）。
    • 同样是因为不知道服务器的MAC地址。
  • 结论：目的IP是广播，目的MAC是广播。

2. DHCP提供 (DHCP Offer) & 4. DHCP确认 (DHCP ACK)

这两个报文的发送方和地址特性完全相同。

  • 发送方：DHCP服务器。
  • 网络层 (IP)：
    • 目的IP地址：255.255.255.255 （受限广播IP地址）。
    • 为什么？ 因为此时客户端还没有正式获得IP地址。如果服务器使用单播IP（如预分配的192.168.1.100）回复，这个数据包到达客户端后，客户端的IP协议栈会认为这个目标是别人的地址而将其丢弃。因此，必须使用IP广播，确保所有主机（包括没有IP的客户端）都会处理这个包。
  • 数据链路层 (MAC)：
    • 目的MAC地址：客户端的MAC地址（单播MAC地址）。
    • 为什么？ 服务器在第一步收到的DHCP Discover报文中，已经看到了客户端的源MAC地址。因此它知道客户端的物理地址，可以直接进行链路层的单播。
  • 结论：目的IP是广播，目的MAC是单播。这正是题目所问的情况。

记忆技巧与常见考点

  • 考题-ARP/DHCP地址类型：这是最高频的考题形式，要求准确判断不同报文的目的IP和MAC地址类型。
  • 理解为什么DHCP Offer/ACK是IP广播：这是最容易错的地方。关键记住客户端在收到ACK前都没有正式IP，服务器无法对其进行IP单播。
  • 理解为什么DHCP Offer/ACK是MAC单播：因为服务器已经从Discover/Request报文中知道了客户端的MAC地址，无需再进行MAC广播。
